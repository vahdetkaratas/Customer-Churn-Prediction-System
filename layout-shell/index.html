Customer churn scoring API

End-to-end tabular ML: stratified split, model comparison (ROC-AUC winner), F1-tuned threshold export, single joblib pipeline for serving, plus FastAPI inference and pytest coverage.

Limitations & scope

  • Demonstration training uses the public Telco Customer Churn dataset; useful scores on your accounts require retraining and validation on your own labeled data.
  • The HTTP API exposes POST /predict with one JSON record per request. There is no server-side CSV upload or batch queue in this codebase.
  • Risk bands (high / medium / low) use fixed probability cutoffs for UI grouping; the binary churn label uses a threshold read from training outputs (see metrics).
  • The published Docker image is inference-only: you mount a trained joblib artifact plus metric files from the training pipeline (see README).
  • Risk bands do not encode business cost matrices or uplift models.

Overview

Binary churn scoring on tabular customer attributes: a fitted sklearn Pipeline (column preprocessing + classifier) loaded at inference time. Training selects among logistic regression, random forest, and gradient boosting using hold-out ROC-AUC, then exports metrics, threshold tables, and a single joblib artifact so encoding and imputation match serving.

The running service exposes POST /predict with a JSON body aligned to the training schema. The response includes a scalar churn probability, a thresholded Yes/No label, fixed-cutoff risk bands for triage, and the threshold applied from disk when present.

Workflow

Offline training vs online inference:

  1. 1

    Train (host / CI)

    Load CSV → feature helpers (e.g. tenure buckets, active-service counts, numeric TotalCharges) → stratified split → fit preprocessor + candidate models → pick best ROC-AUC → write churn_model.joblib, metrics.json, threshold CSV/JSON, and optional error-analysis exports.

  2. 2

    Serve

    uvicorn src.api.app:app or Docker with volumes for the model and reports/metrics/. No training inside the inference container.

  3. 3

    Score

    Client sends one record as JSON; service mirrors training feature steps, runs predict_proba, applies the stored threshold for the label, and maps probability to band text.

Features

Single pipeline artifact

Preprocessor and model serialized together—reduces train/serve skew on encodings and imputation.

FastAPI + OpenAPI

/docs and /redoc for contract review; health endpoint for ops checks.

CLI parity

Optional python -m src.cli.predict for stdin/file JSON using the same inference path as the API.

Threshold + bands

F1-guided threshold persisted from training outputs; separate probability bands for coarse routing in demos.

Tech stack

  • Core: Python, pandas, NumPy, scikit-learn, joblib, PyYAML
  • Serving: FastAPI, Pydantic, uvicorn
  • Quality: pytest (API, preprocessing, CLI, config)
  • Packaging: Docker image running uvicorn; compose bind-mounts model + metrics

Deployment / live interface

Canonical scoring URL for integration checks: https://churn-api.vahdetkaratas.com/ (OpenAPI at /docs). There is no in-repo dashboard UI; interaction is HTTP API–first (try-it flows via OpenAPI or curl).

This static site (e.g. churn.vahdetkaratas.com vs churn.vahdetlabs.com) is informational framing only unless you add client-side calls to the API; browsers may be blocked by CORS unless the API allows your origin.

Why this project

It demonstrates the usual production-minded checkpoints—reproducible training script, compared models, explicit metrics artifacts, inference-only container, and tests around the API boundary—without layering a separate dashboard framework on top.
