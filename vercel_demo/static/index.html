Live inference for a churn model trained on the IBM Telco Customer Churn dataset. Adjust fields below or open /docs for the full JSON schema.

About this project

What it does. Given contract type, tenure, charges, and service flags, the API returns churn probability, a binary prediction (using an F1-tuned threshold from training), and a simple risk band.

How it was built. End-to-end pipeline in Python: feature engineering aligned with training, comparison of Logistic Regression / Random Forest / Gradient Boosting, best model by ROC-AUC, threshold optimization on the hold-out set. This deploy is inference-only — the trained pipeline lives in model/churn_model.joblib.

  • GET /meta — stack, dataset, training summary (for portfolios)
  • GET /health — API + model file presence

Key findings (notebooks)

Short takeaways from EDA and modeling — full code, plots, and threshold analysis live in the repo.

  • Class balance. ~27% churn; stratified train/test split keeps label proportions stable.
  • Who churns. Month-to-month contracts and shorter tenure drive much higher churn rates than long contracts.
  • Models. Logistic Regression, Random Forest, and Gradient Boosting compared on the hold-out set; the API serves the ROC-AUC winner (see chart).
  • Threshold. Binary predictions use an F1-tuned cutoff on the test set — not a fixed 0.5 — so precision/recall trade-offs match the retention use case.
